# Отчёт по тестовому заданию

## Описание

Решение тестового задания на FastAPI: API для работы с H3-гексагонами 12-го уровня,
заполняющими круг с центром 56° с.ш., 38° в.д. и радиусом 7 км.

## Требования
- Python 3.10+
- pip

## Установка

### macOS / Linux

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### Windows (PowerShell)

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## Запуск

```bash
uvicorn main:app --reload
# Запуск может происходить +- несколько секунд из-за создания датасета :(
```

## Технические решения

### Формирование датасета

Датасет `[ [h3_index, level, cell_id], ... ]` строится на старте приложения (через `lifespan`)

- берётся центральная ячейка `h3.latlng_to_cell(56.0, 38.0, 12)`
- через `h3.grid_disk` берутся все ячейки в радиусе `k` (с запасом)
- каждая ячейка проверяется точным критерием из задания
- `level` и `cell_id` считаются по формулам из задания
- дополнительно строится словарь `{h3_index: (h3_index, level, cell_id)}` для O(1) поиска

### /hex

- Проверяется валидность индекса через `h3.is_valid_cell`.
- Если запрошенный индекс имеет res=12 — ищем его напрямую в словаре
- Если res < 12 — проходим по датасету и берём те ячейки, у которых
  `h3.cell_to_parent(h, q_res) == hex_index`
- Если res > 12 — возвращаем `[]`, так как датасет только на res=12

### /avg

- Для каждой записи датасета вычисляется родитель `h3.cell_to_parent(h, resolution)`
  (или сама ячейка, если `resolution == 12`)
- Группируем `level` по паре `(parent, cell_id)`
- Для каждой группы считаем медиану:
  - нечётное количество — центральный элемент;
  - чётное — среднее двух центральных, округлённое в меньшую сторону (`// 2`)

### /bbox и /bbox_kml

- `border` парсится в список `(lat, lon)`
- Кандидаты получаются через `h3.polygon_to_cells(h3.LatLngPoly(ring), 12)`
- Далее через Shapely проверяется, что гексагон лежит внутри полигона:
  `border_poly.contains(cell_poly)` и `not border_poly.boundary.intersects(cell_poly)`
- Для `/bbox_kml` результат сериализуется в KML: каждый гексагон — отдельный `<Placemark>`
  Координаты в KML идут в необходимом порядке `lon,lat`
  Ответ отдаётся с `Content-Disposition: attachment; filename=bbox.kml` для скачивания файла из браузера

### Замеры

Через `time curl`

Эндпоинт | Время
`/hex?hex=8a11aa648367fff` ~45 ms
`/avg?resolution=0` (первый вызов) ~120 ms
`/avg?resolution=0` (повторный) ~5 ms
`/bbox?border=` зависит от размера полигона

### Архитектурные решения

- Индекс `parent → entries` для всех разрешений строится на старте
  Это даёт O(1) доступ в `/hex` без прохода по датасету
- Кэш `/avg` по resolution — результат считается один раз на каждое
  разрешение, повторные запросы отдают его мгновенно
- Кэш Shapely-полигонов гексагонов — в `/bbox` и `/bbox_kml` полигоны
  ячеек строятся один раз на старте, а не на каждый запрос
- KML-координаты выводятся с полной точностью float, чего с запасом
  хватает для res=12; формат соответствует спецификации KML (`lon,lat,alt`)
